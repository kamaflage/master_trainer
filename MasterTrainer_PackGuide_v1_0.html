01

What a Pack Is

A lesson pack is a .json file containing an array of lesson objects. You import it into the Master Trainer via 📥 Import → Import Lesson Pack. The lessons are added to your active profile and appear immediately in the sidebar.

Any LLM can generate a valid pack. This guide gives you a prompt you paste into any LLM — Claude, Gemini, ChatGPT, Perplexity — with a description of the topic you want to learn, and it outputs a ready-to-import file.

File format
The import handler accepts two formats: { "lessons": [...] } (pack wrapper with metadata) or a bare array [...]. Either works. The pack wrapper is preferred — it lets you include a pack name and version for your own records.
02

Lesson Schema

Each lesson object must follow this schema. The import handler silently skips any lesson missing id or title.

Required Fields

FieldTypeStatusNotes
idstringrequiredUnique across all lessons in the profile. Convention: prefix_nn e.g. aaa_01. Duplicate IDs are skipped on import.
titlestringrequiredShort, specific, action-oriented. Shown in sidebar and detail panel.

Recommended Fields

FieldTypeStatusNotes / Valid values
phasenumberoptional1, 2, or 3. Used for grouping in sidebar. Default: 1.
trackstringoptionalFree text. Groups lessons under a named track in the sidebar.
domainstringoptionalFree text tag. Used for filtering and context in prompts.
whystringoptional1–2 sentences: why this lesson matters to the learner personally. Shown in the "Why This Matters" card. Drives motivation — write it directly to the learner, not about the topic.
difficultystringoptionaleasy · medium · hard
modestringoptionalconcept · drill · workshop · project
estimated_minutesnumberoptionalRealistic session time. Shown in sidebar and detail. Typical range: 15–45.
prerequisitesarrayoptionalArray of lesson IDs that should be completed first. Drives the visual Learning Path in the detail panel. Use exact IDs. Empty array [] is valid.
mastery_criteriastringoptionalSpecific, testable statement of what "done" looks like. Shown in detail panel. Start with "Can…"
tagsarrayoptionalArray of lowercase strings. Free tagging for your own reference.
bloom_levelnumberoptional0–6. Controls the test question difficulty. See Bloom Levels section. 0 = auto-assigned by the app.
prompt_overridestringoptionalIf set, completely replaces the auto-generated session prompt. Must be a complete, self-contained prompt. See prompt_override section. Leave empty string "" to use auto-generation.

Auto-Filled on Import

These fields are set automatically by the import handler. Do not include them — if present they are overwritten.

status → "not-started" session_count → 0 confidence → 0 history → [] added → today's date
03

The prompt_override Field

When prompt_override is a non-empty string, the app sends it to the LLM verbatim instead of the auto-generated prompt. The auto-generated prompt is built from the lesson's metadata (title, why, role, profile, bloom level, mastery criteria). prompt_override bypasses all of that.

Important
Because prompt_override replaces the full prompt, it must be entirely self-contained. It does not inherit the learner's profile, persona, or any other context. Include everything the LLM needs.

When to use it

Use prompt_override when you need behaviour the auto-prompt cannot produce — platform-adaptive lessons, specific pedagogical structures, custom state machines, or highly domain-specific teaching flows. Leave it empty for most lessons and let the app generate the prompt.

Required sections in a prompt_override

A well-structured override covers these six sections. None are mandatory by name — but omitting the concepts they cover degrades lesson quality.

1
ROLE — Who the tutor is, their style, what they do and don't do. Anchors every response.
2
SESSION — Topic, track, difficulty, why it matters, mastery target. Gives the LLM full context.
3
TEACH — What to cover, in what order, how deep. Be specific — vague instructions produce vague teaching.
4
ILLUSTRATE — One concrete worked example. Specify the domain and level of detail expected.
5
TEST — The exact test question, including the Bloom level instruction. Must end with a hard stop instruction.
6
EXECUTION RULES — The two-phase state machine. Phase 1 = teach and stop. Phase 2 = evaluate after learner replies, then output the results block.

The results block format

Phase 2 must output this block exactly — the app parser depends on the format:

=== SESSION RESULTS === CONFIDENCE: [number the learner gives, 1–5] SUMMARY: [one sentence — what was covered] NEXT: [title of the most logical next lesson] MODEL: [name of the LLM running this session] === END ===
04

Import Rules

Know these before building a pack — they determine what gets added and what gets silently skipped.

1
Missing id or title → skipped. Any lesson without both fields is silently ignored. Always include both.
2
Duplicate id → skipped. If a lesson with the same ID already exists in the active profile, the new one is not added. IDs must be unique across the entire profile, not just within the pack.
3
Importing the same pack twice is safe. All duplicates are skipped, existing progress is untouched. The app reports how many were added vs skipped.
4
Prerequisites are not validated on import. You can reference IDs that don't exist yet. The learning path will simply not render those nodes until the lessons are added.
5
Imports are profile-scoped. Lessons are added to the active profile only. Switch profiles before importing if you want them elsewhere.
05

Bloom Levels

The bloom_level field controls the cognitive depth of the auto-generated test question. Set 0 to let the app assign automatically based on session count. Use explicit levels for precise control in prompt_override lessons.

LevelLabelWhat the test asksUse for
1RememberRecall a specific fact or definitionFirst session on a new concept
2UnderstandExplain in own words, no jargonConcept lessons, foundational topics
3ApplyUse the concept to solve a problem from their actual workSkill lessons after concept is understood
4AnalyzeBreak down, compare, identify relationshipsComplex topics, Phase 2–3 lessons
5EvaluateJudge, critique, justify a decisionHard lessons, senior-level thinking
6CreateDesign something new that applies all prior learningCapstone lessons, workshops
06

The Creation Prompt

Paste this into any LLM. Fill in the bracketed sections, then send. The LLM will output a valid importable pack.

Pack Creation Prompt — copy and fill in the brackets
You are building a lesson pack for the ADRIAN Master Trainer — an adaptive learning app that generates session prompts from lesson metadata and sends them to an LLM for teaching. OUTPUT: A single valid JSON object in this exact format: { "pack_id": "short_unique_id", "pack_name": "Human-readable pack name", "pack_version": "1.0", "description": "One sentence describing the pack.", "lessons": [ ...lesson objects... ] } LESSON OBJECT SCHEMA (all fields): { "id": "string — unique, format: prefix_nn e.g. xyz_01", "phase": number — 1, 2, or 3, "track": "string — track name for grouping", "domain": "string — domain tag", "title": "string — short, specific, action-oriented", "why": "string — 1-2 sentences why this matters TO THE LEARNER directly", "difficulty": "easy | medium | hard", "mode": "concept | drill | workshop | project", "estimated_minutes": number, "prerequisites": ["id_of_prior_lesson"], "mastery_criteria": "string — starts with Can… — specific and testable", "tags": ["lowercase", "tags"], "bloom_level": number 0-6 (0 = auto), "prompt_override": "" } RULES: - Every lesson MUST have id and title — these are required by the import handler - IDs must be unique across the entire pack — duplicates are skipped on import - prerequisites must reference IDs that exist within this pack - prompt_override should be empty string "" unless you are building a platform-adaptive lesson (see below) - Do not include: status, session_count, confidence, history, added — these are auto-filled on import - Output raw JSON only — no markdown fences, no explanation, no preamble LEARNER PROFILE: [Describe the learner: their role, existing knowledge, what they already know that's relevant, what they're trying to achieve] PACK REQUEST: [Describe what you want to learn: the topic, the scope, how many lessons, what level to start at, what the end goal is] PACK STRUCTURE GUIDANCE: - Phase 1: foundational concepts, easy-medium difficulty, bloom levels 1-2 - Phase 2: applied patterns and skills, medium difficulty, bloom levels 3-4 - Phase 3: advanced design, governance, capstone builds, hard difficulty, bloom levels 4-6 - Each track should have a coherent thread — lessons within a track build on each other - Prerequisites should form a clear directed graph — no circular dependencies - The why field is the most important motivator — write it as if you know exactly why this matters to this learner personally OUTPUT FORMAT REMINDER: Raw JSON only. No markdown. No explanation. Start with { and end with }.
Tip — platform-adaptive packs
If you want lessons that adapt to whatever LLM is running them (like the AI Agent Architecture pack), set prompt_override with a complete prompt that begins with a platform detection instruction: "Identify yourself and list your active capabilities in this session before teaching." See the AI Agent Architecture pack as a reference.

After the LLM outputs the JSON

1
Copy the full JSON output into a text editor and save as my_pack.json
2
Validate it at jsonlint.com or paste into any JSON validator — fix any parse errors before importing
3
In the Master Trainer: 📥 Import → Import Lesson Pack → select your file
4
The app will tell you how many lessons were added vs skipped

Worked Example

A filled-in creation prompt and the minimal valid lesson object it should produce.

Filled-in prompt (learner profile + pack request)

LEARNER PROFILE: Senior RPA Developer and Technical Lead at a telco. Deep Automation Anywhere A360 experience. Strong with bot architecture, orchestration, and process automation. No prior SQL experience beyond basic SELECT queries. Goal: write and optimize queries for bot reporting and data extraction tasks. PACK REQUEST: SQL for RPA Developers — 8 lessons covering SQL from joins through window functions. Start from intermediate (assumes basic SELECT). End goal: can write and debug complex queries for AA360 reporting integrations. Connect concepts to RPA data access patterns throughout.

Minimal valid lesson object (what the LLM must output for each lesson)

{ "id": "sql_01", "phase": 1, "track": "SQL Foundations", "domain": "sql", "title": "JOINs — How Tables Connect", "why": "Every AA360 reporting query pulls from multiple tables. Without JOINs you are stuck with single-table data or doing manual merges in the bot — both are fragile and slow.", "difficulty": "easy", "mode": "concept", "estimated_minutes": 20, "prerequisites": [], "mastery_criteria": "Can write INNER, LEFT, and RIGHT JOINs. Can explain what NULL rows mean in a LEFT JOIN result.", "tags": ["sql", "joins", "rpa"], "bloom_level": 2, "prompt_override": "" }
What makes this lesson object good
The why speaks directly to the learner's AA360 work — not "joins are useful" but "every AA360 reporting query needs this." The mastery_criteria is testable — you either can or cannot write those three JOIN types. The bloom_level 2 means the test will ask for an explanation in own words — right for a first session on a new concept.
08

Pre-Import Checklist

Run through this before importing any pack.

✓
Valid JSON — paste into jsonlint.com or any validator. Fix all parse errors first.
✓
Every lesson has id and title — missing either causes silent skip on import.
✓
IDs are unique within the pack — and don't conflict with lessons already in your active profile.
✓
Prerequisites reference valid IDs — all IDs listed in prerequisites arrays exist somewhere in the pack or your existing profile.
✓
No circular prerequisites — lesson A requires B requires A is invalid. Prerequisites must form a directed graph with no loops.
✓
prompt_override is complete if set — if non-empty, it must include ROLE, SESSION, TEACH, ILLUSTRATE, TEST, EXECUTION RULES, and the results block format.
✓
Active profile selected — lessons import into the active profile. Confirm you're on the right one before importing.
